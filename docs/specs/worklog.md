# Worklog — спецификация

Что это, зачем, как себя ведёт и на чём держится. Компания и человек здесь не упоминаются: всё, что относится к компании, лежит в её профиле (§7).

## 1. Зачем

Разработчик ведёт одновременно много направлений: задачи в Jira, ветки, MR, договорённости с коллегами, ожидания других команд. Контекст разбросан по вкладкам, чатам и памяти, а к дейлику его приходится собирать заново. Worklog держит всё это в одном окне и пополняется так же быстро, как говорится фраза: из сессии Claude Code или Codex или руками.

## 2. Цели, не-цели, анти-цели

**Цели**
- Все рабочие направления видны разом на доске по статусам.
- Карточка направления хранит весь контекст: тикеты, ссылки, ленту событий, дела, заметки базы знаний.
- Постоянные рабочие ссылки всегда под рукой в сайдбаре.
- Сплошной список дел с перетаскиванием.
- Экран дейлика с готовым текстом в стиле пользователя.
- Поручение агенту в один клик и окно для дополнительного контекста.
- База знаний, которую ведёт Claude и которой пользуется сам.
- Пополнение двумя путями: через сессии агента (Claude Code, Codex или оба) и вручную.
- Вид — как у программ Apple для macOS.
- Установка, проверка и обновление — одной фразой агенту.

**Не-цели**
- Запись в Jira. Этап направления Worklog считает из Jira сам, «Жду» и «Отложено» — ручные пометки поверх.
- Командный доступ, общий сервер, синхронизация, мобильная версия, уведомления, автозапуск.
- Тайм-трекинг и прочие техники продуктивности.
- Управление агентами: лимиты, очереди, конфликты — зона пользователя.
- Чат с агентом внутри приложения: вопросы задаются тем же поручением.
- Закрытие вкладок Chrome — их закрывает сам пользователь.
- Windows и Linux. Редактирование профиля компании из интерфейса.

**Анти-цели** (провал, даже если всё работает)
- **Во внешних текстах видно ИИ.** Текст дейлика, события, которые в него попадают, и всё, что может уйти наружу (Jira, MR, сообщения), — от первого лица единственного числа, без слов «Claude», «агент», «ИИ», «сессия», «сгенерировано». Внутри интерфейса такие слова допустимы.
- Вести приложение тяжело: записать событие дольше, чем сказать фразу. Это главный критерий для всех мелких решений.
- Рабочие данные уходят с машины сверх перечисленного в README («Что уходит с машины»): чтение Jira, `git` к GitLab и текст, который пользователь сам отдаёт агенту (дейлик, поручение).
- Приложение становится ещё одним источником хаоса вкладок.
- Выжимка из сессий выдумывает то, чего не было: найденные автоматически пункты помечены и требуют подтверждения.
- База знаний дублирует README, код или вики.
- Секрет (токен Jira, пароль сертификата) оказывается в чате, транскрипте, файле репозитория или логах.
- Установка или обновление молча обходит сбой, перезаписывает чужое (скиллы, данные, настройки Claude) или теряет данные.
- В репозитории оказывается что-то о конкретной компании или человеке.

## 3. Направления, статусы, дела

- **Направление** — единица учёта: название, тикеты, ссылки, лента событий, дела, заметки, порядок в колонке, даты.
- **Статусы:** В работе, Жду (с «кого жду»), В мерж реквесте, Тестирование, Ждёт релиза, Отложено, Готово. У направления с тикетами из проектов профиля этап считается из их статусов в Jira по самому отстающему и руками не ставится; «Жду» и «Отложено» — пометки поверх этапа, только ручные; когда все такие тикеты закрыты, направление уходит в «Готово». Смена этапа пишется в ленту событием «Jira». Направления без таких тикетов ведутся руками.
- **Дела:** сплошной список с перетаскиванием; у дела — направление, «от кого», срок, время, одна ссылка. Выполненное дело с направлением пишет событие в его ленту.
- **Повторяющиеся дела:** правило (каждый день, по будням, по дням недели) раз в день кладёт дело наверх со сроком «сегодня»; второе, пока не сделано первое, не появляется; пропущенные дни не догоняются; в «Сегодня:» дейлика не попадают.
- **Сделано:** готовые направления по месяцам года с графиком и поиском по всем годам; дата «сделано» ставится сама, задним числом — из CLI.

## 4. Окно

- **Сайдбар:** Дела, Доска, Дейлик, История, Знания, Сделано, группы постоянных ссылок с описаниями (ⓘ), в самом низу — «Разобрать вкладки Chrome», «Проверить обновления» и «Как пользоваться». Ссылки открываются в обычном Chrome. «Разобрать вкладки Chrome» открывает облачко: что сделает агент, фраза для своей сессии и «Запустить агента», когда запуск настроен; закрывается по Esc, клику мимо и повторному нажатию.
- **Вкладки и разделение:** доска, дела, экраны и любое направление открываются вкладками; вкладку можно перетащить вправо — окно делится на две панели. Набор вкладок запоминается.
- **Доска:** колонки по статусам; карточка — название, тикеты, «жду: кого», счётчик дел, отметка «агент работает».
- **Направление:** тикеты со статусами Jira, ветка задачи с копированием, стенды, сборки и Storybook по сегментам (§7), ссылки с описаниями (MR появляется сам), лента, дела, заметки.
- **Отмена:** ⌘Z/⌘⇧Z для изменений из окна, пока работает сервер.
- **Онбординг:** при первом открытии окна — экскурсия облачками (доска, «＋», ссылки из вкладок Chrome, карточка, дела, перетаскивание дела на карточку, направление, лента, поручение агенту, меню, вкладки рядом, дейлик, «здесь ничего не сломать») с готовыми фразами для агента; она сама открывает нужные вкладки, пропускает шаг без цели на экране и в конце возвращает раскладку. Пройденная или закрытая, сама она больше не появляется; «Как пользоваться» в сайдбаре запускает её снова. «Первые шаги» — кнопка «Первые шаги 2/4» с кольцом прогресса в правом нижнем углу области вкладок (при двух панелях — в углу правой), поверх любой вкладки; экраны оставляют под ней запас прокрутки. Нажатие разворачивает над ней карточку с четырьмя пунктами — завести направление, разложить вкладки Chrome по направлениям, записать событие, добавить дело — с фразами для агента; сворачивается повторным нажатием, Esc и кликом мимо, при открытии окна свёрнута. Пункты отмечаются по данным, вкладки — первым успешным `worklog tabs`. «Показать» сворачивает карточку и открывает облачко у нужного поля; пока идёт экскурсия, кнопки нет. «Скрыть» прячет её до «Как пользоваться»; когда пройдены все четыре пункта, кнопка исчезает насовсем, даже если потом данные снимут отметку. Новому пользователю без данных сервер один раз создаёт пример-направление с фиктивными тикетами, ссылками, событиями, делом и заметкой: в дейлик, Историю, «Сделано», опросы Jira и MR и поиск CLI по названию он не попадает, агента в нём не запустить. Состояние онбординга — `data/onboarding.json`, вне ⌘Z.
- **Обновление:** справа в полосе вкладок — «Обновить Worklog», когда на GitHub вышла новая версия (бледная, с подсказкой «обновите через git», если в клоне свои правки или коммиты), «Обновляю… 0:42», пока идёт обновление (выжимка дейлика в это время недоступна), и «Перезагрузить», если окно не может перезагрузиться само: поле в фокусе, открыто окно поручения или меню. После перезагрузки — те же вкладки и прокрутка панелей; сбой — в полосе ошибок, прежняя версия остаётся.
- **Вид:** нативный macOS, светлая и тёмная темы; фронт не ходит в сеть (шрифты и фавиконы локальные: фавиконы — из кэша Chrome).

## 5. Дейлик и История

- Период — с прошлого проведённого дейлика (по умолчанию с 11:30 предыдущего рабочего дня). Экран: что сделано, кого жду, справа — текст.
- Без нажатий текст собирается шаблоном из событий. «✦ Собрать из сессий» читает сессии всех установленных агентов (Claude Code, Codex) за период, и основной агент одним вызовом (`claude -p` или `codex exec` без сохранения сессии) получает пункты «что сделал», кандидатов в дела и прозу в стиле пользователя. Правки пользователя не затираются; пункты ✦ можно убрать или перепривязать, кандидатов — принять или отклонить. Под текстом — предупреждение о словах про ИИ.
- «Дейлик прошёл» переносит текст и пункты в Историю и начинает новый период. История — лента по дням с поиском.

## 6. Агенты: Claude Code и Codex

- У коллеги Claude Code, Codex или оба. Основной агент пишет текст дейлика и стоит по умолчанию в окне поручения; скиллы, дейлик и поручение работают для каждого установленного.

- **Скиллы:** записать что угодно одной фразой («запиши в worklog по сео: аналитик подтвердил баг бэка»), «разбери вкладки» (открытые вкладки Chrome раскладываются по направлениям по номерам задач, пользователь подтверждает), «запиши в базу», `/worklog` (в Codex `$worklog`, только по прямому вызову) в конце сессии (список предложений по сделанному, пишется только подтверждённое), установка и обновление. Скиллы лежат в клоне, агенты видят их через симлинки.
- **CLI** — единственный путь записи для агента; работает и при закрытом окне, открытое окно обновляется само. Codex пишет в данные из песочницы, если папка данных есть в его `writable_roots`.
- **База знаний:** заметка — заголовок, несколько строк, ссылки на файлы проекта (с строкой) и страницы. Не дублирует README и код: факт уже есть — одна строка и ссылка. Claude читает заметки направления перед работой над ним.
- **Поручение агенту:** шаблон (Выполнить задачу, Декомпозировать, Изучить доки, Вопрос, Своё), контекст из карточки галочками, дополнительный текст, ветка (из тикетов по профилю, иначе базовая), агент, если установлены оба (по умолчанию последний выбранный). Запуск открывает вкладку выбранного терминала с интерактивным `claude` или `codex` в папке проекта; в промпте — задание, контекст и правила: сначала ветка, коммит и пуш только по просьбе, результаты — в Worklog через CLI после подтверждения, от первого лица. Пока агент работает — отметка с временем; снимает её агент или пользователь.
- **Разобрать вкладки Chrome:** поручение без направления и дела, только из облачка в сайдбаре (в окне поручения его нет), основным агентом в том же терминале и папке. Агент разбирает вкладки по скиллу `worklog-chrome-tabs` и записывает только после подтверждения; правил про ветку, коммиты и `git status` в промпте нет — он работает только с CLI Worklog. Отметки «агент работает» нет: её негде показать.

## 7. Компания: профиль

Один JSON с номером версии формата, лежит у пользователя в `~/.config/worklog/profile.json`, источник (ссылка на файл в GitLab или путь) запоминается для обновления.

- **Jira:** адрес, нужен ли клиентский сертификат, поле сегментов, соответствие статусов этапам (по имени и по началу имени), цвета статусов.
- **Проекты:** префикс ключа → метка платформы; ссылка на тикет строится из адреса Jira.
- **Ветка:** префикс, разделитель ключей, базовая ветка.
- **Сегменты, стенды, сборки, Storybook:** шаблоны адресов по платформам и сегментам, замены в имени ветки. Видны сегменты из Jira, остальные — по «＋».
- **GitLab:** SSH-хост и порт, адрес MR. MR находится по `git ls-remote origin` в папке проекта: голова MR равна голове ветки.
- **Виды ссылок** (вики, CI) и **стартовые ссылки сайдбара**; `{gitlabUser}` в адресе заменяется логином пользователя.

Профиль новее или старее кода — понятная ошибка «обнови worklog» / «обнови профиль». Без профиля Worklog — обычный трекер: без Jira, платформ, веток, стендов и MR. Тикет с платформой, которой профиль не знает, читается и показывается как есть.

## 8. Машина, данные, установка

- **Сервер:** Node на `127.0.0.1:4317`, отдаёт собранный фронт и API, держит SSE для окон и выключается через 3 минуты без окон. Запуск — `Worklog.app` на рабочем столе: поднять сервер, если не поднят, и открыть или поднять окно Chrome в режиме приложения.
- **Данные:** `data/` в клоне — JSON и Markdown, читаются глазами, запись атомарная под блокировкой. У `data/` свой git, в репозиторий кода она не входит; сервер раз в день коммитит изменения, если за день коммита ещё не было. Новая версия, меняющая формат, переводит данные при старте сервера.
- **Настройки машины:** `~/.config/worklog/env` (`WORKLOG_ИМЯ=значение`): папка проекта, основной агент (`WORKLOG_AGENT`), пути к node, `claude` и `codex`, терминал (Warp, iTerm2, Terminal), редактор (JetBrains, VS Code, Cursor или никакого — тогда файлы из заметок не открываются), отложенная Jira (`WORKLOG_JIRA=off`), логин GitLab, источник профиля. Порядок: переменная окружения → файл → умолчание.
- **Секреты:** токен Jira и пароль сертификата — в связке ключей, сам сертификат — файлом с правами 600.
- **Установка** — агентом по `INSTALL.md`: каждый шаг проверяется `worklog doctor` и повторяется без вреда; пароль набирает пользователь, токен попадает в связку ключей через буфер обмена; чужое не перезаписывается без вопроса; без профиля, без Jira (её можно отложить до сертификата) и без редактора установка доходит до конца. **Обновление:** снимок данных, `git pull --ff-only` (при локальных правках — стоп), зависимости, сборка, перезапуск сервера, скиллы, `doctor`.
- **Обновление по кнопке:** сервер при старте и раз в 6 часов делает `git fetch` отслеживаемой ветки клона, без вопросов о паролях; кнопка запускает отдельный процесс, который проходит шаги обновления, перезапускает сервер и при любом сбое возвращает прежние код, сборку, профиль и — если новая версия успела их переписать — данные из снимка. `WORKLOG_UPDATE_CHECK=off` выключает проверку (так идут тесты и демо).
- **`worklog doctor`:** окружение, папка проекта, профиль, `env`, сборка, сертификат и токен, ответ Jira (различает токен, сертификат и сеть), порт, скиллы и CLI, терминал и редактор, данные — для каждой проверки «ок» или что сломано и как чинить; есть JSON для агента; секреты не печатаются.

## 9. Модель данных

- **Direction:** id, название, статус и пометка, `waitingFor`, `example` у примера онбординга, тикеты (ключ, платформа, ссылка, последний статус и сегменты из Jira), ссылки (название, адрес, вид, описание), события, порядок, даты.
- **Event:** время, текст от первого лица, источник (`manual`, `claude`, `session-summary`, `jira`, `system`).
- **Todo:** id, текст, направление, `requestedBy`, срок, время, ссылка, правило повтора, `done`, `doneAt`, порядок.
- **RepeatRule:** текст, дни, направление, «от кого», время, ссылка.
- **QuickLinkGroup:** название, ссылки с описаниями.
- **AgentRun** хранит и агента (`claude`, `codex`; нет поля — `claude`).
- **Daily / DailyDraft:** период, текст, пункты, кандидаты.
- **Note:** id, заголовок, тело, направления, файлы (путь и строка), адреса, `updatedAt`.
- **AgentRun:** id, направление или дело, шаблон, ветка, `startedAt`, `finishedAt`.
- **Onboarding:** `tourClosedAt`, `stepsHidden`, `exampleCreatedAt`; нет файла — экскурсию не видели, пример не создавали.
